# TODO for rai

- [x] When the server is restarted, and the volume is encrypted, `rai-ssh` fails and `rai-unlock` fails too. `rai-ssh` fails with a "mkdir - access denied" or something similar, and `rai-unlock` fails with "sudo: Sorry, I can't do that" (I'm assuming it's the mount). Fixed in a4582b3/5601775.
- [x] Dedupe the boilerplate repeated across `rai-ssh`, `rai-push`, `rai-pull`, `rai-cp`, `rai-code`, `rai-start`, `rai-unlock`: getting/validating `provider_ip` and computing `remote_path` from `RAI_REPO_ROOT`. It's already drifted — `rai-pull`'s "Could not get VM IP" error goes to stdout while `rai-push`'s goes to stderr, and `rai-start`/`rai-code`/`rai-ssh` don't validate the IP at all, so a bad IP there surfaces as a raw `ssh`/`code` error instead of a clear message. Pull into shared `require_ip`/`remote_repo_path` helpers, likely sourced from `rai-config` or a new `rai-common`. Fixed in fb16bda.
- [x] No `set -euo pipefail` in any script, so failures get silently swallowed unless someone remembered a manual `|| exit 1`. E.g. `rai-push`'s remote repo-setup `ssh` call (creating `.git`, setting `receive.denyCurrentBranch`) has no error check, so a failure there doesn't stop the subsequent `git push`. Adding it needs care: `rai-cp`'s `src="$1"; dest="$2"` would throw "unbound variable" under `set -u` with too few args before reaching the usage message, so positional args need `${2:-}` first. Fixed in 2801480/737ef23/fd876e0.
- [x] Remote commands are built by interpolating values (`$remote_path`, `$branch`, repo dir name) into a double-quoted string passed to a remote shell, itself using single quotes (e.g. `cd '$remote_path'`) in `rai-ssh`/`rai-push`/`rai-unlock`. A repo name or branch containing a `'` breaks the quoting. Worth hardening (e.g. pass values as positional args to a remote script) since the whole point of this tool is running less-trusted code/VMs. Fixed in 94f8469/b92f5c0/2fe0a70/b28a0da via a `shell_quote` helper.
- [x] `rai-provider-hetzner`'s `provider_status`/`provider_ip` pipe `hcloud ... | jq -r ...` without checking `hcloud`'s exit code, so an `hcloud` failure prints `null`/empty instead of surfacing the real error. `provider_start`'s `while [ "$(provider_status)" != "running" ]` loop would then spin forever printing dots instead of failing. Fixed in 15a5782.
- [x] `RAI_STATIC_IP` is missing from `rai-config`'s `_rai_config_vars` preset/restore list, so unlike every other `RAI_*` var, an exported `RAI_STATIC_IP` gets silently overwritten if either `.rai/config` file also sets it — breaking the documented "env vars always win" precedence for exactly this one var. Fixed in c7419f3.
- [x] `rai-push`'s final remote `git checkout '$branch'` isn't checked for success, but `git update-ref "$lease_ref" "$branch"` runs before it regardless. If the remote working tree has uncommitted changes (e.g. from AI edits) that conflict with the incoming branch, the checkout fails silently and the lease still records success — so the next `rai push` trusts a lease that's lying about the remote actually being in sync. Fixed in 12fd45f.
- [x] `rai-push`'s remote setup (`mkdir` + `git init` + `git config receive.denyCurrentBranch updateInstead`) only runs `if [ ! -d '$remote_path/.git' ]`, i.e. once at creation, with no migration path. Any future one-time remote-config change won't retroactively apply to already-initialized remote repos. Fixed in 438e6d0.
